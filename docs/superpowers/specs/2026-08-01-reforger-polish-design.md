# Super Reforge 重铸台交互与展示完善设计

日期：2026-08-01  
状态：待用户审核  
适用版本：Minecraft 1.21.1、NeoForge 21.1.244

## 1. 目标

本次迭代只完善现有 Super Reforge 的展示和交互，不改变已经确定的重铸规则、数据驱动优先级或持久化架构。需要解决三个用户可见问题：

1. 重铸台界面信息不完整，缺少方便浏览的完整概率列表和详细属性说明。
2. 方块实体锤子的姿态错误，静止状态就与砧面、后方支架发生明显穿模。
3. 模组物品没有独立且顺序明确的创造模式页签。

## 2. 已确认的产品决策

- GUI 使用“熔核锻造日志”方向。
- 概率区域必须显示服务器给出的全部等级和词条记录，不能因为屏幕高度直接截断。
- 概率列表支持鼠标滚轮和可拖动滚动条。
- 列表保持紧凑；鼠标悬停具体词条时，再显示完整 Attribute 数据。
- 权重仍使用自动归一化：例如权重 `20、30、30` 的最终概率分别为 `20 / 80`、`30 / 80`、`30 / 80`。
- 锤子改为竖直悬挂的动力锻锤，锤柄朝上、锤头朝下。
- 新增独立的 `Super Reforge` 创造模式页签。
- 动画专用锤子不出现在创造模式页签中。

## 3. GUI 设计

### 3.1 总体布局

界面延续原版容器的像素风格，使用深色锻铁边框、铜色分隔线和熔核橙色高亮。界面由三部分组成：

- 左上操作区：目标物品槽、重铸媒介槽、消耗信息和重铸按钮。
- 右上锻造日志区：等级概率和该等级下的词条概率。
- 下方玩家物品栏：完整保留原版槽位行为及提示。

界面宽高可以在现有 `256 × 198` 基础上适度增大，以保证日志可读性；菜单槽位坐标与屏幕绘制坐标必须同步调整。界面仍需能在常用 GUI 缩放下完整显示。

### 3.2 锻造日志内容

日志按以下层级排列：

1. 等级行：显示等级名称和该等级最终概率。
2. 词条行：缩进显示词条前缀名称和该词条最终概率。

最终词条概率采用联合概率：

`等级最终概率 × 该等级内词条归一化概率`

如果某一级别没有可用于当前目标物品的词条，该级别不进入有效概率总和，并沿用服务端现有候选筛选结果。客户端不自行推测物品类型或重算服务端候选池。

列表绘制使用裁剪区域，超出区域的内容不会覆盖玩家物品栏。现有按纵坐标直接 `break` 的截断逻辑将被滚动模型替代。

### 3.3 滚动行为

日志区维护独立的滚动偏移量：

- 鼠标位于日志区时，滚轮上下滚动列表。
- 右侧显示滚动轨道和滑块；滑块高度反映可见内容占总内容的比例。
- 鼠标可以拖动滑块快速定位。
- 列表内容不足一页时隐藏或禁用滚动条，并将偏移量归零。
- 预览数据更新、目标物品变化或界面重新初始化时，对偏移量执行边界钳制，避免空白页。
- 滚动事件只在指针位于日志区或滚动条上时消费，不影响其他容器操作。

### 3.4 悬停详细信息

指针悬停某一词条行时显示 Minecraft 标准 Component 提示框。提示内容包括：

- 完整词条名称及样式。
- 词条 ID，便于数据包或 KubeJS 作者排错。
- 每条 Attribute 的注册 ID。
- 固定数值，或随机数值的最小值至最大值范围。
- 运算方式：固定加算、百分比加算或乘算。
- 作用位置：主手、副手、护甲槽或通用 Curios 槽。

候选词条的随机种子尚未生成，因此随机 Attribute 在预览中显示配置范围，不伪造一次“未来结果”。完成重铸后，物品仍按照既有 `词条 ID + 随机种子` 架构解析出确定数值。

详细信息优先读取已经由服务器同步到客户端的展示定义。未知 Attribute 或同步数据缺失时显示其 ID 和“定义不可用”提示，界面不得崩溃。

### 3.5 状态与错误提示

- 无目标物品：日志区显示放入目标物品的提示。
- 目标不支持重铸：显示不匹配任何物品类型。
- 无有效媒介：显示所需媒介和数量。
- 经验不足：保留明确的经验不足状态。
- 服务端预览达到安全上限：显示“预览内容已达到同步上限”的警告，不能让用户误以为被截断的条目概率为零。
- 动画执行期间：按钮不可重复触发，操作区显示约一秒的锻造进度。

如现有预览负载没有“达到上限”标记，则在负载中增加只读布尔状态；它只影响展示，不改变重铸抽取逻辑。

## 4. 锤子穿模修正

### 4.1 已定位的原因

截图和当前资源共同证明问题来自复合旋转，而不是单独的高度误差：

- `ReforgerBlockEntityRenderer` 对锤子施加 X 轴 90°旋转。
- `forge_hammer.json` 的 `fixed` 显示变换又施加 Z 轴 -45°旋转。
- 两个变换叠加后，原本竖直建模的锤子横躺并斜跨方块。
- 当前 `0.72` 缩放和静止高度让横置锤头进一步进入后方横梁及中央砧面。

### 4.2 新姿态

锤子使用统一、可计算的渲染姿态：

- 锤柄沿世界竖直方向向上。
- 锤头位于锤柄下方，横向对准中央砧面。
- 方块朝向仅控制锤头的水平朝向，不改变竖直轴。
- 移除物品模型和渲染器之间重复的倾斜变换。
- 使用专门的方块实体展示变换，不依赖手持或 GUI 展示姿态。

静止时锤头底面与砧面顶面保持约 1–2 个模型像素的可见间隙；落锤最低点让锤头底面刚好接触砧面。锤子整体适度缩小并向工作区中央或前方校正，确保四种方块朝向下都不会进入后方横梁和左右立柱。

### 4.3 动画

保留现有约一秒的节奏：

1. 起始阶段短暂停顿并蓄力。
2. 锤子加速落下。
3. 接触砧面时熔核达到最亮并产生火花。
4. 锤子轻微回弹后回到静止位置。
5. 服务端完成结果更新，客户端显示新词条。

锤子高度继续由同步的剩余 tick 推导，不增加每 tick 网络包。只调整姿态、缩放、锚点以及静止/接触高度。

### 4.4 可验证几何边界

将静止高度、接触高度、缩放和锚点集中为有名称的常量或纯计算方法，避免散落魔法数字。测试至少验证：

- 静止高度高于接触高度。
- 动画高度始终处于二者之间，回弹除外但不得超过设计上界。
- 最低点不会低于中央砧面顶面。
- 四种朝向共用一致的竖直边界。

游戏内再从正面、侧面和俯视角度检查实际烘焙模型，确认没有视觉穿模。

## 5. 独立创造模式页签

新增注册类管理 `CreativeModeTab`，页签标题使用翻译键，图标使用重铸台物品。内容固定按以下顺序排列：

1. 重铸台。
2. 普通重铸媒介。
3. 高级重铸媒介。
4. 终极重铸媒介。

动画专用 `forge_hammer` 是内部渲染物品，不放入页签。它仍保持注册，以供方块实体渲染器创建 `ItemStack`。

页签注册加入现有统一注册入口，确保所有物品已经声明后再引用其 `DeferredHolder`。新增中英文翻译键，避免显示未翻译 ID。

## 6. 代码注释与文件说明

本次修改触及的 Java 和 JSON 文件都要补充有效注释：

- Java 类注释说明职责和影响范围。
- 对滚动状态、概率计算边界、锤子坐标系等不直观逻辑添加行内注释。
- JSON 使用 `_comment` 解释模型用途和关键变换。
- 清理所触及文件中因编码异常而显示为乱码的既有中文注释。
- 更新 `docs/FILE_REFERENCE.md`，说明新增文件、修改文件及其对游戏行为的影响。

注释解释“为什么”和坐标/协议约束，不逐行复述代码。

## 7. 测试策略

开发遵循先写失败测试、再实现的顺序。

### 7.1 单元测试

- 日志行模型包含全部等级和词条，不按可见高度丢弃数据。
- 权重归一化和联合概率显示正确。
- 滚动最大值、钳制、滚轮步进和滑块比例正确。
- 固定值与随机范围能生成正确的悬停说明。
- Attribute 运算方式和槽位能映射为可读 Component。
- 锤子静止、落点、回弹及四向边界计算正确。
- 创造页签内容顺序正确且不包含动画锤子。

### 7.2 集成与回归验证

- 运行完整 Gradle 测试套件。
- 构建客户端和服务端类，确认可选 Curios、KubeJS 不会变成硬依赖。
- 使用现有核心、Curios、KubeJS 和组合服务端配置进行启动验证。
- 进入游戏检查 GUI 的滚轮、拖动、悬停、按钮状态和玩家物品栏槽位对齐。
- 分别朝北、东、南、西放置重铸台，检查静止及动画锤子。
- 检查独立 `Super Reforge` 页签的图标、翻译、顺序和隐藏物品。
- 重新构建最终 JAR，并记录文件路径、大小和 SHA-256。

## 8. 不在本次范围内

- 不新增 Super Reforge 自有 Attribute。
- 不改变 datapack、KubeJS 与全局 config 的优先级。
- 不改变等级模式、点数模式或阶段倍率语义。
- 不改变重铸媒介的抽取规则和实际服务器随机结果。
- 不把动画锤子变成可正常获取或使用的游戏内容。
- 不重新设计重铸台整个方块模型；仅校正动态锤子的姿态和边界。

## 9. 完成标准

以下条件同时满足时，本次迭代才算完成：

- GUI 能通过滚轮或滚动条查看服务器预览中的全部记录。
- 悬停任意候选词条可看到其完整 Attribute 范围、操作方式和槽位。
- 锤子在静止与完整动画期间不再穿过砧面、后梁或立柱。
- 创造物品栏出现独立 `Super Reforge` 页签，顺序正确且不包含动画锤子。
- 所触及代码具有可读注释，文件参考文档已更新。
- 自动测试、构建和四种兼容启动配置全部通过。
- 生成新的可安装 JAR。
